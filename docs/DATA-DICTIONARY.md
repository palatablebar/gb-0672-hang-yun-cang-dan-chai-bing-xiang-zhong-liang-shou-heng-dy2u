# 舱单数据定义

id是主单、分组单或箱货明细唯一字符串编号，parent为空表示主单。节点申报件数、净重和毛重是其完整子树的申报总量，校验时只加直接子节点，避免多层重复计数。包装carton=1件，pallet=10件；重量kg与t统一为kg。件数必须非负整数，净重非负且毛重不得低于净重。
拆并结构采用每节点最多一个父级的有向图；自环、长环、缺父级均阻断封存，保留环路径。不会以平面求和替代逐层校验。
危险品按明确分类与UN编号检查，3类与5.1类禁止同箱；未知分类和缺失编号需复核。此演示规则只覆盖文中三类，不替代运输合规审批。
报关总量只汇总主单，与context.json内的申报件数、净重和毛重逐项比较。重复同值折叠，重复编号冲突全部隔离。原始计数=采纳+隔离+空行+重复表头+重复同值行。
封存需所有图、重量、危险品和采信问题处理完毕。数值均Decimal，对外字符串保留精度，编号不转整数。

## 订舱确认单（M8 booking）

船公司回执只按整箱报告件重（`container,pieces,gross_kg`），不拆主单。订舱确认单把回执整箱量与舱单按主单（根节点）汇总的箱内件重逐箱比对，输出每箱 `已接受 / 待补证 / 退回`。

- 计量口径：只汇总箱内主单根节点，子单/分单不参与加总，避免多层重复计数；确认后的箱内明细按主单原样回写（`allocations`），不做二次加总。
- 已接受：舱单主单合计的件数与毛重均与回执整箱值对平，且箱归属唯一主单。
- 待补证：件重对不平（`WEIGHT_MISMATCH` + `UNCOVERED_CARGO`）、回执漏报该箱（`NO_RECEIPT`），或同箱挂多张主单归属不清（`MULTI_SOURCE`）。归属不清时确认单不覆盖，各主单原明细全部保留，待人工拆清后重判。
- 退回：回执同箱号重复且件重不一致（`RECEIPT_DUPLICATE`，不采信任何一条），或回执箱号在舱单无任何主单归属（`UNKNOWN_CONTAINER`）。重量未对平或来源重复的箱不得进入确认计量。
- 同箱重复且整箱件重完全一致时折叠为一条并记录 `receipt_count`；不一致才判来源重复。
- 放行裁决：`proven`（默认，赶截单）先放行可证明的已接受箱，问题箱留待补证，结论为“部分放行可证明箱”；`whole` 要求每个箱都说得清来源，全部已接受才“整票交接”，否则“不予交接”。
- 确认事务：确认失败（无任何已接受箱）返回 `CONFIRMATION_FAILED/409` 且旧版确认单保留；同一回执重跑按裁决印章 `seal` 幂等，不新增第二套；新回执产生新版本，旧版置“历史”不删除。
